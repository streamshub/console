= Checking topic messages

[role="_abstract"]
Track the flow of messages for a specific topic from the *Messages* tab.
The *Messages* tab presents a chronological list of messages for a topic.

.Procedure

. Log in to the Kafka cluster in the StreamsHub Console, then click *Topics*.
. On the *Topics* page, click the name of the topic you want to inspect.
. Check the information on the *Messages* tab.
+
For each message, view the timestamp (in UTC), offset, key, and value.
+
Click on a message to view the full message details.
+
Click the *Manage columns* icon (represented as two-column icon) to choose the information to display.

. Use the filter above the table to refine the messages that are retrieved.
+
Each change to the filter retrieves the messages again.
Messages appear in the table as they are read from Kafka.

. Check the status below the filter to see how many messages were found and how long the retrieval took.

Filter options:: The following options are available.
+
* *Partition* to retrieve messages from all partitions or from a specific partition.
* *Fetch from* to set the starting point for returning messages:
** *Latest* to start from the latest messages.
** *Last 5 minutes*, *Last 10 minutes*, or *Last 15 minutes* to start from a time relative to now.
** *Offset* to start from an offset in a partition. In some cases, you may want to specify an offset without a partition.
However, the most common scenario is to search by offset within a specific partition.
** *Timestamp* to start from an exact time and date.
** *Unix timestamp* to start from a time and date in Unix format.
* *Limit* to set the maximum number of messages to return, in steps of 50. The default is 50.

Searching messages:: Enter a search term in the *Search* field to return only the messages that contain it. 
The search field is available when *Fetch from* is set to anything other than *Latest*.
+
Choose where to look for the term:
+
* *Everywhere* to match the key, headers, or value.
* *Key*, *Headers*, or *Value* to narrow the search to one part of the message.
+
The search is performed by the console server, which reads records from the starting point and checks each one against the search term.
The term matches any part of the text and ignores case.
Use the following wildcards in the term:
+
* `*` to match any sequence of characters, including none.
* `?` to match any single character.
+
For example, `order-*-failed` matches `order-1234-failed`, and `order-?-failed` matches `order-7-failed` but not `order-12-failed`.
Because the term can match any part of the text, you do not need to add `*` at the start or end.
+
Because the full key, headers, and value are checked, a message is found even if the matching text is beyond the part shown in the table.
+
Searching can take time on a topic with many records.
Choose a narrower starting point, such as a specific partition or a recent time, to search faster.

Retrieval status:: The status below the filter shows progress while messages are being retrieved. 
+
* While retrieving, the status shows the time the retrieval has been running and the maximum time left, for example `0:12 elapsed, 4:48 left`. 
During a search, a progress bar estimates how much of the topic has been scanned.
The maximum time is set by the administrator who deployed the console. 
The retrieval ends sooner if all records are read or the requested number of messages is found.
* Click *Cancel* to stop a retrieval. The messages found so far remain in the table.
* When the retrieval finishes, the status shows the number of messages and how long it took, for example `50 messages in 0:01`. 
For a search, it shows the number of matches and the number of records scanned, for example `7 matches from 98,765 scanned in 1:23`. 
A search also shows why it ended:
** *Scan complete* means all records from the starting point were checked.
** *Found all requested matches* means the *Limit* was reached. More matches might exist.
** *Timed out, partial results* means the maximum time ran out before all records were checked. More matches might exist. To find them, narrow the search or ask your administrator to increase the maximum time.
** *Stopped, partial results* means the retrieval was cancelled.
