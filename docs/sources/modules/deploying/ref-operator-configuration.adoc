= Configuring the console operator

[role="_abstract"]
You can configure the console operator's runtime behaviour by setting environment variables on the operator `Deployment`.
These settings apply globally across all `Console` instances managed by the operator and must be applied by a cluster administrator.

How you set these variables depends on how the operator was installed:

* **OLM installations** — add a `spec.config.env` block to the `Subscription` resource.
* **Non-OLM installations** — add entries to the `env` list of the operator container in the `Deployment` manifest before applying it to the cluster.

Changes to these environment variables take effect after the operator pod restarts.

== KafkaUser Secret access review

The operator checks whether each Console ServiceAccount is authorized to read the
Strimzi-generated Secret referenced by `kafkaClusters.credentials.kafkaUser` before it
uses the credentials. This protects credential Secrets when a Console references a
Kafka cluster or KafkaUser in another namespace.

`CONSOLE_SERVICE_ACCOUNT_ACCESS_REVIEW_DENIED_ACTION`::
Controls what the operator does when a SubjectAccessReview denies the Console
ServiceAccount `get` access to a referenced KafkaUser Secret. The setting applies
globally to all Console instances managed by the operator. Supported values are:

* `PRESERVE` (default) — sets a `SecurityError` condition and leaves the Console
  configuration workflow not ready. Existing owned resources are preserved unchanged,
  including any denied KafkaUser credentials already present in an existing
  `ConsoleSecret` and deployed Console configuration. This option prevents new
  updates but does not remove credentials that were already deployed.
* `REMOVE` — the most secure option — sets a `SecurityWarning` condition and continues
  reconciliation without the denied Kafka cluster connection. Existing generated
  configuration is updated, so denied KafkaUser credentials and their cluster
  connection are removed from an existing Console. `REMOVE` may become the default
  in a future release.
* `IGNORE` — continues reconciliation and uses the denied credentials despite the
  failed authorization check. This option bypasses the security protection.

The actual MicroProfile configuration property is
`console.service-account.access-review.denied-action`. When configuring the operator
through environment variables, replace periods with underscores and use the
upper-case form shown above. For example:

[source,yaml]
----
# OLM Subscription or operator Deployment container environment
- name: CONSOLE_SERVICE_ACCOUNT_ACCESS_REVIEW_DENIED_ACTION
  value: "PRESERVE"
----

Changes take effect after the operator pod restarts. Values are case-insensitive;
other values prevent the operator from starting with a valid configuration.

[WARNING]
====
`IGNORE` bypasses the authorization protection and can allow a Console author to cause
credential Secret data to be copied across namespaces. Use it only as a deliberately
reviewed migration or compatibility exception, and do not use it for normal production
deployments or when Console authors are not fully trusted.
====

IMPORTANT: `REMOVE` provides the strongest protection because it removes denied credentials
from generated Console configuration, including configuration already used by an existing
deployment. Although `PRESERVE` is the current default to avoid unexpected changes during
upgrade, consider using `REMOVE` for new deployments. The default may change to `REMOVE`
in a future release.

If access is denied while using `PRESERVE`, grant the per-Console ServiceAccount
`get` access to the exact Secret in the Secret's namespace, then allow reconciliation
to run again. See xref:proc-connecting-console-{context}[Deploying and connecting the
console to a Kafka cluster] for the Role and RoleBinding examples.

== Default API image

The operator uses a built-in default API container image when a `Console` instance does not specify one explicitly.
This image is set at build time and corresponds to the version of the operator being run.

`CONSOLE_DEPLOYMENT_DEFAULT_API_IMAGE`::
Overrides the built-in default API container image used when a `Console` custom resource does not specify `spec.deployment.spec.template.spec.serverContainer.image`.
+
The value must be a fully qualified image reference, including registry, repository, and tag or digest.
For example: `quay.io/my-org/console-api:1.0.0`.
+
This is most useful when running a custom or mirrored build of the console API in an environment where the standard `quay.io/streamshub/` images are not accessible.
If you set this variable, ensure the new default image's registry prefix is also included in `CONSOLE_DEPLOYMENT_ALLOWED_IMAGE_PREFIXES`, or leave the allowlist unset so it is derived automatically from the new default.

== Permitted container image prefixes

By default, the operator allows `Console` instances to reference any API container image whose registry path begins with the same prefix as the operator's built-in default image (`quay.io/streamshub/`).
You can broaden or restrict this set by configuring an explicit allowlist of permitted image prefixes.

=== Configuration

`CONSOLE_DEPLOYMENT_ALLOWED_IMAGE_PREFIXES`::
A comma-separated list of image reference prefixes.
When a `Console` custom resource specifies an API container image (via `spec.deployment.spec.template.spec.serverContainer.image`), the operator checks that the image begins with at least one entry in this list.
If the image does not match, the operator sets an `ERROR` condition on the `Console` resource and does not create or update the console `Deployment`.
+
When this variable is not set, the operator derives a single permitted prefix from its built-in default image by taking everything up to and including the last `/`.
For a standard release, that is `quay.io/streamshub/`.
If the default image contains no `/`, the operator permits only the default image itself.

=== Important considerations

* **Prefix matching uses literal string comparison.**
An image is permitted if its full reference begins with any entry in the list — no wildcards or patterns are supported.
Include the trailing `/` in each prefix to prevent unintended matches across similarly-named organisations.
For example, `quay.io/my-org/` permits `quay.io/my-org/console-api:latest` but not `quay.io/my-org-other/image:latest`.

* **The explicit list replaces the default entirely.**
Once `CONSOLE_DEPLOYMENT_ALLOWED_IMAGE_PREFIXES` is set, the operator no longer applies the derived default.
If the configured list does not include the prefix of the default API image, any `Console` instance that omits an image override — and therefore falls back to the default — will be rejected at reconcile time.
The operator logs a warning at startup when this condition is detected.
+
To avoid this, either include the default image's prefix in the list, or update `CONSOLE_DEPLOYMENT_DEFAULT_API_IMAGE` to point to an image whose prefix is already in the list.

* **Validation occurs during reconciliation, not at resource creation.**
A rejected image surfaces as an `ERROR` condition on the `Console` resource with `reason: RECONCILIATION_EXCEPTION` and a message that includes both the rejected image and the configured prefixes.
The `Console` resource remains in `Ready=False` until the image reference is corrected or the operator is reconfigured and restarted.
No console `Deployment` is created or modified while the validation error is present.

* **An operator restart is required for changes to take effect.**
The allowlist is loaded once when the operator starts.
Updating the environment variable on the `Subscription` or `Deployment` triggers a pod rollout; new restrictions apply once the operator pod is running again.

=== Example: restrict images to a private registry

The following examples configure the operator to permit only images from a private organisation's registry, and update the default API image to one in that registry.

.OLM installation — `Subscription` resource
[source,yaml]
----
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: streamshub-console-sub
spec:
  name: streamshub-console-operator
  channel: alpha
  source: streamshub-console-catalog
  sourceNamespace: ${NAMESPACE}
  config:
    env:
      - name: CONSOLE_DEPLOYMENT_DEFAULT_API_IMAGE
        value: "quay.io/my-org/console-api:1.0.0"
      - name: CONSOLE_DEPLOYMENT_ALLOWED_IMAGE_PREFIXES
        value: "quay.io/my-org/"
----

.Non-OLM installation — operator `Deployment` manifest
[source,yaml]
----
containers:
  - name: streamshub-console-operator
    env:
      - name: CONSOLE_DEPLOYMENT_DEFAULT_API_IMAGE
        value: "quay.io/my-org/console-api:1.0.0"
      - name: CONSOLE_DEPLOYMENT_ALLOWED_IMAGE_PREFIXES
        value: "quay.io/my-org/"
----

To permit images from multiple registries without changing the default, provide a comma-separated list that includes the default image's prefix:

[source,yaml]
----
- name: CONSOLE_DEPLOYMENT_ALLOWED_IMAGE_PREFIXES
  value: "quay.io/my-org/,quay.io/streamshub/"
----
